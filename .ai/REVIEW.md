# Review Guide

## Review Goal

코드 취향을 강요하는 것이 아니라 실제 결함, 회귀, 보안 위험, 유지보수 비용을 찾는다.
요청이 리뷰만인 경우 사용자 승인 없이 코드를 수정하지 않는다.

## Review Order

1. 요구사항과 실제 동작의 불일치
2. 데이터 손실, 보안, 권한 문제
3. 런타임 오류와 경계 사례
4. API·스키마·호환성 파괴
5. 동시성, 트랜잭션, 성능 문제
6. 테스트 누락과 운영 관측성
7. 가독성과 유지보수성

## Finding Format

각 발견에는 다음을 포함한다.

- 심각도: Critical / High / Medium / Low
- 정확한 파일과 좁은 줄 범위
- 어떤 조건에서 문제가 발생하는지
- 사용자 또는 시스템에 미치는 영향
- 최소 수정 방향
- 근거가 불확실하면 확인 방법

## Evidence Rules

- 코드에서 재현 가능한 경로를 따라간다.
- 이미 처리되는 문제를 중복 지적하지 않는다.
- 저장소 관례와 다른 것만으로 결함이라고 하지 않는다.
- 테스트 부재 자체보다 테스트 부재로 놓치는 구체적인 위험을 설명한다.
- 확신이 낮은 내용은 단정하지 않는다.

## Review Checklist

- 요구사항의 모든 경로가 구현되었는가?
- 실패·빈 값·경계 값이 안전한가?
- 인증 후 객체 수준 권한도 확인하는가?
- 트랜잭션과 동시성 결과가 예상 가능한가?
- 로그와 응답에 민감 정보가 없는가?
- 공개 계약 또는 저장 데이터가 깨지지 않는가?
- 쿼리 수, 메모리, 네트워크 호출이 입력 크기에 따라 폭증하지 않는가?
- 테스트가 중요한 동작과 회귀를 검증하는가?

발견 사항이 없으면 그렇게 명확히 말하고, 실행하지 못한 테스트나 남은 위험을 별도로 적는다.
