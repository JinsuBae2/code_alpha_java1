# Reusable AI Workspace

이 디렉터리는 AI 코딩 도구와 일관되게 협업하기 위한 재사용 가능한 규칙 모음이다.
특정 제품에 종속되지 않으며 Codex, ChatGPT, Claude Code, Gemini CLI, Cursor 등에서
필요한 파일을 선택해 사용할 수 있다.

## 설계 원칙

- 확인된 사용자 선호와 프로젝트 사실을 구분한다.
- 저장소의 실제 코드와 문서를 추측보다 우선한다.
- 작은 변경, 명시적 검증, 솔직한 완료 보고를 기본으로 한다.
- 전역 규칙은 짧고 안정적으로 유지하고 프로젝트별 사실은 `PROJECT_RULES.md`에 둔다.
- 규칙이 충돌하면 더 구체적이고 현재 작업에 가까운 지침을 우선한다.

## 파일 안내

| 파일 | 역할 |
|---|---|
| `AGENTS.md` | 모든 작업에 적용되는 핵심 행동 규칙 |
| `CONTEXT_LOADING.md` | 작업별 최소 문서 선택과 토큰 절약 규칙 |
| `AI_PHILOSOPHY.md` | AI 협업 철학과 판단 기준 |
| `DEVELOPER.md` | 확인된 사용자 성향과 확인이 필요한 항목 |
| `LEARNING.md` | 학습·멘토링 모드 규칙 |
| `CODING_RULES.md` | 언어에 독립적인 코딩 규칙 |
| `BACKEND_RULES.md` | Java/Spring 계열 백엔드 규칙 |
| `API_RULES.md` | HTTP API 설계·변경 규칙 |
| `VIBE_CODING.md` | 기능 단위 구현 흐름 |
| `PROJECT_RULES.md` | 저장소별 사실을 기록하는 템플릿 |
| `REVIEW.md` | 코드 리뷰 기준 |
| `CHECKLIST.md` | 작업 완료 전 점검표 |
| `MEMORY.md` | 장기 기억 후보와 제외 기준 |
| `DECISION.md` | 기술 결정 기록 방식 |

## 저장소에 적용하기

1. 이 `.ai` 디렉터리를 저장소 루트에 복사한다.
2. `PROJECT_RULES.md`의 대괄호 항목을 실제 저장소 정보로 채운다.
3. 이 수정본에 포함된 루트 `AGENTS.md`를 함께 복사한다. 이 파일은 `.ai/AGENTS.md`와
   작업별 추가 규칙을 명시적으로 연결하므로, 루트 `AGENTS.md`만 자동 인식하는 도구에도
   적용된다. 이미 루트 `AGENTS.md`가 있다면 기존 지침을 덮어쓰지 말고 병합한다.

4. 기술 버전과 실행 명령은 추측해 넣지 말고 빌드 파일과 CI 설정에서 확인한다.
5. 규칙 변경도 코드 변경처럼 검토하고, 중복되거나 지켜지지 않는 규칙은 제거한다.

## 우선순위

1. 사용자의 현재 요청
2. 저장소 루트의 지침
3. 하위 디렉터리의 더 구체적인 지침
4. `.ai/PROJECT_RULES.md`
5. 이 디렉터리의 공통 규칙
6. 도구의 일반적인 관례

상위 지침이나 안전 정책과 충돌하는 규칙은 적용하지 않는다.

## 토큰 효율적인 문서 사용

모든 문서를 매 작업마다 읽지 않는다. 일반 질문은 `.ai` 문서 없이 답하고, 저장소 관련
작업은 `CONTEXT_LOADING.md`의 작업별 최소 문서만 읽는다. 실제 변경이 필요한 경우에만
`AGENTS.md`를 기본 규칙으로 추가하며, API·백엔드·리뷰 등 전문 규칙은 해당 작업일 때만
읽는다.

## 권장 운영

- 개인 성향은 `DEVELOPER.md`에 둔다.
- 변하지 않는 협업 원칙은 `AGENTS.md`와 `AI_PHILOSOPHY.md`에 둔다.
- 현재 기술 스택, 경로, 명령, 아키텍처는 `PROJECT_RULES.md`에 둔다.
- 작업 중 결정은 `DECISION.md` 형식으로 저장소의 ADR 또는 이슈에 남긴다.
- 완료 전에는 `CHECKLIST.md`, 리뷰 시에는 `REVIEW.md`를 사용한다.

## 사용자 프로필 템플릿

`DEVELOPER.md`와 `MEMORY.md`는 예시 사용자 프로필을 포함한다. 재사용할 때는 해당
내용을 현재 사용자에게 확인된 정보로 교체하거나, 확인 전에는 비워 둔다.

현재 예시에는 다음과 같은 선호가 들어 있다.

- Java와 Spring Boot 중심의 백엔드 개발에 관심이 있다.
- 단계별 설명, 코드 예제, 실무 연결을 선호한다.
- 결론을 먼저 듣고 이유와 검증 방법을 이어서 보는 방식을 선호한다.
- AI가 실제 파일을 읽고 작은 단위로 구현·검증하기를 원한다.
- 기본 대화 언어는 한국어다.

Java 버전, 빌드 도구, 운영체제, Flutter 사용 여부 등 충돌하거나 원본 확인이
필요한 정보는 전역 기본값으로 고정하지 않았다. Java/Spring 프로젝트가 아니라면
`BACKEND_RULES.md`는 적용하지 않는다.
