## 1. 시간 복잡도의 정의와 필요성

### (1) 시간 복잡도(Time Complexity)의 정의
시간 복잡도란 알고리즘이 실행되는 과정에서 입력 데이터의 크기($N$)에 따라 **얼마나 많은 연산(시간)이 소요되는지**를 수학적으로 나타낸 지표입니다. 실제 걸리는 절대적인 시간(초)이 아니라, 데이터 증가에 따른 연산 횟수의 증가 추세를 측정합니다.

### (2) 시간 복잡도 분석의 필요성
* **하드웨어 독립적 평가:** 알고리즘의 성능은 실행하는 컴퓨터의 CPU, 메모리 성능에 따라 달라집니다. 시간 복잡도는 하드웨어 성능과 무관하게 알고리즘 자체의 객관적인 효율성을 평가할 수 있게 해줍니다.
* **대용량 데이터 대응:** 본 과제의 제약 조건처럼 문자열의 길이가 최대 $10^6$(100만) 자에 달할 때, 효율적인 알고리즘과 비효율적인 알고리즘은 실행 시간에서 수 시간에서 수일 이상의 극적인 차이를 만들어냅니다. 따라서 개발 단계에서 병목을 예측하고 방지하기 위해 필수적입니다.

## 2. Big-O 표기법의 개념과 상황별 예시

### (1) Big-O 표기법의 개념
Big-O(빅오) 표기법은 알고리즘의 최악의 경우(Worst Case)의 성능을 점근적으로 표현하는 방법입니다. 데이터가 무한히 커질 때 성능에 가장 큰 영향을 미치는 **최고차항만 남기고 상수를 무시**하여 단순화합니다.

### (2) 상황별 주요 예시

| 표기법           | 명칭 | 설명 및 예시 |
|:--------------| :--- | :--- |
| **O(1)**      | 상수 시간 (Constant Time) | 데이터 크기와 무관하게 항상 일정 횟수만 연산 (예: 스택의 `push`/`pop`) |
| **O(\log N)** | 로그 시간 (Logarithmic Time) | 연산을 거칠 때마다 데이터 크기가 절반으로 감소 (예: 이진 탐색) |
| **O(N)**      | 선형 시간 (Linear Time) | 데이터 크기에 비례하여 연산 횟수 증가 (예: 단일 단방향 `for`문) |
| **O(N^2)**    | 2차 시간 (Quadratic Time) | 데이터 크기의 제곱에 비례하여 증가 (예: 이중 `for`문을 이용한 정렬) |

## 3. RoadToBiodome02 코드의 시간 복잡도 분석

작성된 자바 코드는 입력받은 문자열의 길이를 N이라고 할 때, 크게 3가지 핵심 연산 단계로 나뉩니다.

### (1) 회문(Palindrome) 검사 단계
* **로직:** `while (start < end)` 문을 통해 문자열의 양 끝에서 중심을 향해 좁혀오며 비교합니다.
* **연산 횟수:** 최악의 경우(회문인 경우) 문자열 길이의 절반인 N/2번 비교 연산을 수행합니다.
* **시간 복잡도:** 최고차항의 상수 배수를 제외하므로 O(N)입니다.

### (2) 스택 데이터 삽입(Push) 단계
* **로직:** `for`문을 순회하며 문자열의 모든 글자를 한 자씩 직접 구현한 `push()` 메서드로 배열에 쌓습니다.
* **연산 횟수:** `push()` 내부의 인덱스 증가 및 배열 대입 연산은 O(1)이지만, 이를 N번 반복합니다.
* **시간 복잡도:** O(N)입니다.

### (3) 스택 데이터 출력(Pop) 단계
* **로직:** `while (!isEmpty())` 문을 통해 스택이 빌 때까지 `pop()`을 호출하여 화면에 출력합니다.
* **연산 횟수:** `pop()` 내부 연산은 O(1)이며, 스택에 쌓인 N개의 데이터를 모두 꺼내므로 N번 반복합니다.
* **시간 복잡도:** O(N)입니다.

### 📌 총합 시간 복잡도
알고리즘의 실행 흐름에 따라 각 단계의 복잡도를 더하면 다음과 같습니다.

* **전체 연산:** O(N) [회문] + O(N) [Push] + O(N) [Pop] = O(3N)

Big-O 표기법의 상수 제거 규칙에 따라, 이 프로그램의 최종 시간 복잡도는 O(N)으로 매우 효율적인 선형 시간 복잡도를 가집니다.

## 4. 병목 현상 분석 및 최적화 방안

### (1) 병목 현상(Bottleneck) 발견
이론적인 알고리즘 시간 복잡도는 O(N)으로 최적에 가깝지만, 실질적인 실행 성능에서 가장 큰 병목이 발생하는 지점은 스택 출력 단계의 `System.out.print(pop())`입니다.

* **원인:** 자바의 `System.out.print()`는 메모리 내부 연산이 아니라 운영체제(OS)의 콘솔 화면 출력 스트림을 직접 호출하는 I/O(입출력) 연산입니다. 입력 데이터가 최대치인 100만 글자일 때, 메모리 연산은 순식간에 끝나지만 OS 입출력 버퍼를 100만 번 따로 호출하게 되면서 CPU 가동 효율이 극도로 떨어지고 엄청난 실행 시간 지연(병목)이 발생합니다.

### (2) 최적화 방안
과제 제약사항상 `StringBuilder`는 사용할 수 없습니다. 따라서 가용한 대안으로 **결과 저장용 `char[]` 문자 배열을 메모리에 미리 할당**하는 방법을 사용합니다.
* **해결책:** `pop()`할 때마다 매번 출력하는 대신, 입력 문자열과 동일한 크기의 `char[] result` 배열을 생성하여 `pop()`된 문자들을 메모리 상에서 먼저 채워 넣습니다. 이후 완성된 배열을 `new String(result)`을 통해 단 **1번의 출력 연산**으로 처리하면 시스템 호출 횟수를 N번에서 1번으로 획기적으로 줄일 수 있습니다.

## 5. 보너스 과제: 최적화 코드 적용 및 복잡도 비교

### (1) 최적화 개념 코드 구조 비교

**기존 코드 (I/O 병목 발생):**
```java
while (!isEmpty()) {
    System.out.print(pop()); // N번의 콘솔 I/O 발생 (병목 지점)
}

char[] result = new char[args[0].length()];
int idx = 0;
while (!isEmpty()) {
    result[idx++] = pop(); // 메모리 상의 배열에 저장 (O(1))
}
System.out.println(new String(result)); // 단 1번의 콘솔 I/O로 출력 완료
