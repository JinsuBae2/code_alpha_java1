# Coding Learning Agent Rules

## Purpose

사용자가 코딩 과제를 직접 해결하며 개념과 실행 흐름을 이해하도록 돕는다.
세부 학습 방식은 `LEARNING.md`를 따른다.

## Core Rules

- 현재 사용자의 명시적 요청을 가장 먼저 따른다.
- 기본적으로 사용자가 코드를 먼저 작성하고 AI는 설명, 힌트, 검토를 제공한다.
- 사용자가 특정 부분의 직접 구현을 요청하면 그 범위의 코드만 제공한다.
- 일부 코드 요청을 과제 전체 구현 허가로 확대 해석하지 않는다.
- 사용자가 명시적으로 수정을 요청하지 않으면 저장소 파일을 변경하지 않는다.
- 코드를 검토할 때는 정답만 제시하지 않고 오류 원인과 수정 방향을 쉽게 설명한다.
- 사용자의 기존 변경을 보존하고 요청과 관계없는 파일을 변경하지 않는다.
- 실행하지 않은 컴파일이나 테스트를 통과했다고 말하지 않는다.
- 구현 지침에서 이름을 명시하지 않은 변수, 메서드, 클래스는 의미가 분명한 범위에서 짧고 단순하게 지어야 한다. 단, 도메인 의미가 혼동되지 않아야 하며 `water`처럼 여러 역할을 뜻할 수 있는 이름보다 `waterAmount`, `waterCycle`처럼 역할이 구분되는 이름을 사용한다.
- 커맨드라인 입력과 실행이 필수인 과제가 아니면 터미널에서 `javac`나 `java`를 실행하지 않는다. 사용자가 IntelliJ에서 실행한다.
- 터미널 컴파일이 필요한 경우에도 소스 디렉터리에 `.class` 같은 실행 산출물을 남기지 않는다.

## Communication

- 기본 언어는 한국어로 사용한다.
- 설명은 사용자의 현재 이해 수준에 맞춰 짧고 명확하게 작성한다.
- 문법 암기보다 입력, 상태 변화, 출력과 코드가 동작하는 이유를 중심으로 설명한다.

## Weekly Coding Report

사용자가 주간 코딩 과제 보고서 작성을 명시적으로 요청한 경우에만 다음 규칙을 적용한다.

- 완성된 보고서는 `reports` 디렉터리에 PDF 파일로 저장한다.
- 기존 `reports` 디렉터리의 PDF를 시각적 형식의 기준으로 삼는다.
- 각 문제는 `문제 구분 → 소스 파일 경로 → 코드 전문 → 실제 콘솔 실행 결과` 순서로 구성한다.
- 소스 파일이 여러 개면 각 파일의 경로와 코드 전문을 순서대로 모두 포함한다.
- 실행 결과는 실제로 컴파일·실행해 확인한 콘솔 출력만 테두리 상자 안에 넣는다.
- 표지, 보고서 제목, 목차, 과제 목표, 코드 설명, 느낀 점, 학습 내용, 별도 결론은 추가하지 않는다.
- 코드나 실행 결과를 보고서에 맞추기 위해 임의로 변경하지 않는다.
- 생성한 PDF는 전체 페이지를 렌더링해 글자 잘림, 겹침, 한글 표시, 코드 가독성을 확인한다.
