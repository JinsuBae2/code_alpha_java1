# Long-term Memory Policy

이 문서는 특정 AI 제품의 메모리에 그대로 저장하기 위한 명령이 아니라, 저장해도 되는
장기 정보와 저장하면 안 되는 임시 정보를 구분하는 기준이다.

## Example Memory Candidates (replace after confirmation)

아래 항목은 예시이며, 재사용 시 현재 사용자가 명시적으로 기억해 달라고 했거나
반복적으로 확인된 정보로만 교체한다.

1. 기본 소통 언어는 한국어다.
2. Java와 Spring Boot 기반 백엔드 개발에 관심이 있다.
3. 결론을 먼저 듣고 단계별 설명을 이어서 보는 방식을 선호한다.
4. 코드 예제와 실제 프로젝트 적용 방법을 함께 보는 것을 선호한다.
5. AI가 기존 파일과 구조를 먼저 확인한 뒤 최소 범위로 수정하기를 원한다.
6. 구현 후 빌드·테스트 등 실제 검증 결과를 명확히 보고받기를 원한다.
7. 학습에서는 정답 암기보다 원리, 선택 이유, 실무 연결을 중시한다.

## Do Not Store as Long-term Memory

- 특정 저장소의 현재 브랜치와 작업 상태
- 일회성 오류, 과제, 시험, 일정
- 곧 바뀔 라이브러리와 프레임워크 버전
- API 키, 토큰, 계정, 개인정보
- 확인되지 않은 숙련도, 직업, 장기 목표
- 한 번만 등장한 도구·운영체제·IDE 선호
- 종료된 프로젝트의 세부 구현

## Update Rules

- 사용자가 명시적으로 기억해 달라고 한 정보만 우선 추가한다.
- 민감 정보는 요청받아도 메모리에 저장하지 않는다.
- 기존 항목과 충돌하면 새 값을 덮어쓰기 전에 충돌을 확인한다.
- 더 이상 맞지 않는 항목은 수정하거나 제거한다.
- 프로젝트별 정보는 이 파일 대신 `PROJECT_RULES.md`에 기록한다.
