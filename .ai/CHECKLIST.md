# Completion Checklist

모든 항목을 기계적으로 강제하지 말고 변경 위험에 맞는 항목을 선택한다.

## Scope

- [ ] 사용자의 요청과 완료 조건을 충족했다.
- [ ] 관련 없는 파일이나 포맷을 변경하지 않았다.
- [ ] 기존 사용자 변경을 보존했다.
- [ ] 가정과 미확인 사항을 기록했다.

## Correctness

- [ ] 정상 경로를 확인했다.
- [ ] 중요한 빈 값, 경계 값, 실패 경로를 확인했다.
- [ ] import, 타입, 이름, 경로가 실제 프로젝트와 일치한다.
- [ ] 동시성 또는 트랜잭션 영향이 있다면 검토했다.

## Compatibility and Data

- [ ] 공개 API 호환성을 확인했다.
- [ ] 스키마 또는 저장 형식 변경을 명시했다.
- [ ] 마이그레이션과 롤백 필요성을 검토했다.
- [ ] 기존 데이터 손상 가능성을 확인했다.

## Security and Operations

- [ ] 인증과 권한을 각각 확인했다.
- [ ] 비밀값과 개인정보가 코드·로그·응답에 노출되지 않는다.
- [ ] 오류 처리와 로그가 운영에서 원인을 찾기에 충분하다.
- [ ] 새 의존성과 외부 서비스의 위험을 검토했다.

## Verification

- [ ] 관련 포맷·정적 검사를 실행했다.
- [ ] 관련 테스트를 실행했다.
- [ ] 필요한 전체 빌드 또는 테스트를 실행했다.
- [ ] 실행한 명령과 결과를 정확히 보고했다.
- [ ] 실행하지 못한 검증과 이유를 보고했다.

## Handoff

- [ ] 무엇이 왜 바뀌었는지 설명했다.
- [ ] 변경 파일을 명확히 제시했다.
- [ ] 남은 위험과 후속 작업을 구분했다.
- [ ] 사용자가 재현할 실행·테스트 방법을 제공했다.
